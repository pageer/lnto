# Runtime requirements — shared by local dev and production host.
#
# History: the original pins were Flask 2.0.1-era (see git history). When the
# host moved to Python 3.11 and the local machine to 3.14/3.15, those pins
# became unbuildable; the 2026-11 security pass then pushed the set to the
# current versions, chosen to clear all open Dependabot pip alerts while
# keeping the app's model/view code working unchanged.
#
# Notes:
# - Flask 3.1.x required by the Flask session CVE alert (Vary: Cookie).
#   Needed the matching major bumps: Flask-SQLAlchemy 3.1.x and
#   SQLAlchemy 2.1.x. The models keep the legacy Query API, which 2.x still
#   supports; changes required were: drop convert_unicode Column kwarg
#   (lnto/libs/links.py), fix a two-target .join() call (lnto/libs/tags.py),
#   and rework tests/db.py for the per-app engine/metadata model.
# - Werkzeug 3.1.9 clears all Werkzeug alerts (debugger RCE, multipart DoS,
#   Windows safe_join family). Flask 2.2.x is NOT compatible with Werkzeug
#   3.1 (removed werkzeug.__version__).
# - Mako 1.4.x, python-dotenv 1.2.x, soupsieve 4.x clear their respective
#   alerts (TemplateLookup path traversal, set_key symlink overwrite, CSS
#   parser ReDoS family).
# - WTForms 3.1.x pairs with Flask-WTF 1.2.x. forms.py imports URLField from
#   wtforms directly (wtforms.fields.html5 was removed in 3.0) and the
#   strip-filter lambdas guard against None (3.x runs filters on None).
# - PyMySQL is the DB driver. Locally the app uses SQLite (default
#   SQLALCHEMY_DATABASE_URI), so PyMySQL is simply unused; on the host,
#   config.py uses the mysql+pymysql:// scheme. Pure Python, installs
#   everywhere — no MySQL headers needed.
# - Dev tools live in requirements-dev.txt; greenlet is not needed
#   (no asyncio).
